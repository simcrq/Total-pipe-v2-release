# 复合科研布局：评估与开发计划

## 实施前的架构评估（2026-10-24）

- Deck IR 已有 `schema_version: "2.0"`，正文由平面的 `blocks`、`figure_refs` 和 `graphics` 定义。
- 图形的 `composite` 只组合原生图形，不是可以混排证据图、正文和公式的页面区域树。
- 编译器已有页面框架、公式测量、图片等比放置、流程/DAG/Path IR 绘制和 QA。
- RPA 管理完整页面版式及精确槽位；它不调用 OfficeCLI。PWF 提取资源，pwf2rpa 原样传递科学证据。
- 因此在现有模块内扩展即可，不建立 HTML 管线或独立布局系统。

## 公共契约

在 `composition.layout_tree` 增加可选区域树，支持 `1.0/1.1`。外层 Deck IR 仍为 2.0；旧平面表示继续有效。
`regions.body` 复用当前页面框架的正文区域，禁止自定义页面坐标。容器使用相对权重、预设间距和内边距。

- 容器：`columns`、`stack`、`panel`、`image_grid`。
- 叶节点：`block` 引用正文或公式块 ID，`figure` 引用 `figure_refs` 的零基索引，`graphic` 引用现有图形 ID；1.1 的 `table` 引用原生科研表格 ID。
- 内容仍只在原来的数组中保存。每项内容必须恰好引用一次；公式及其显式解释锚点必须留在同一垂直组。
- 深度最多 6、节点最多 64；列最多 4、图片网格最多 12 图。标题保留完整术语。
- 输入语义、测量需求、最终几何分别记录。结构化反馈绑定 slide ID、组件路径、需求和实际区域，附修复动作。
- 图形绘制器继续只接受编译后的合法矩形；所有旧科学证据和可读性检查保留。

## 实施顺序

1. **Deck IR 垂直切片**：严格验证；自底向上测量、自顶向下分配；复用现有文字、公式、图片和原生图形发射器；原子失败；独立反馈 JSON；绕过平面 packer。
2. **RPA 子布局**：独立子布局检索与组合接口；只输出语义结构及引用；基于消费者能力筛选；不改写整页 320 个模板，不声称已通过几何验收。
3. **资源元数据**：PWF 输出图像尺寸/格式/宽高比/保守裁剪策略；pwf2rpa 保持工作流原样并补齐显式资源引用对应的 visual 元数据；RPA 保留这些字段。
4. **文档和能力**：编译器能力查询、RPA 能力声明、Skill 和中文用法；明确缺少能力时的回退和失败流程。
5. **验收**：三栏科研组合、矩阵/根号公式、流程图和贝塞尔图在子区域内的构建；结构错误、窄区域反馈、内容完整性和旧平面 IR 回归。

## 已实现范围与边界

实施状态：区域树、现有发射器接入、结构化反馈、RPA 独立子布局接口和图片元数据传递已实现。
三页混排样例已通过几何编译、PowerPoint 原生检查和独立视觉复核。
第二轮补齐自动子布局推荐与复杂原生表格；没有 body_compositions 的旧规划不改写页面结构。

- 水平流程图有现成最小节点尺寸；三栏通常容不下。返回空间不足，换两栏/整行或拆页，不缩小节点字体。
- 原生科研表格支持多级合并表头、跨行跨列及公式/矩阵格；每页最多 4 表、每表最多 32 行/12 列。
  数据缺失、计算和科学结论仍由上游明确提供，不能把截图宣称为可编辑表格。
- 不自动创造科学结论、不自动裁剪科研证据、不静默丢内容，不在编译器内无限循环调用 RPA。
- 文字与纯文字表格采用既有 `preserve-terms` 策略：保留原文并标记 REVIEW；含公式表格、公式、图片和图形的几何下限仍必须满足。

## 第二轮开发与验收（自动选型、原生表格）

1. **自动选型**：RPA plan_sublayout 在有限目录内筛选，保留完整分组与引用；
   根据消费者能力、组尺寸下界、正文区域大小及当前 SHA 反馈筛选并输出相对权重。
   create_deck_plan.body_compositions 接入同一入口，compact 保留完整树；旧页规划继续有效。
   未知/重复 slide ID、缺失内容、旧能力或过期反馈明确重规划；validate_deck_plan 不放行失败子布局。
2. **语义表格**：Deck IR 的布局树 1.1 引用 composition.tables；严格覆盖逻辑网格并绑定论文证据。
   编译器测量完整文字、合并行列和公式 AST，在 18 pt 下限以上分配；OfficeCLI 写单个原生表格。
   实际对象的坐标、内容、合并、数学及样式与计划核对，保留科学与原生测量 REVIEW。
3. **实际渲染修正**：修正 LDLᵀ、带上下标单位等词元换行；垂直对齐写入 tcPr.anchor，
   公式格尊重 align，表格颜色使用当前主题。逻辑坐标决定测量顺序，重排 cells 不改变留白。
4. **开发样例**：新增两页 native-table.deck_ir.json，覆盖多级合并表头、分解矩阵、
   子区域中的根号/分式/指数与正文混排，保留数学软件回归边界。

- 新增两页样例经过 PowerPoint 直接检查、同次原生 PDF 导出及独立 PNG 复核，两页 PASS。

## 第三轮：行内公式与混排容量

- 正文块和原生表格文字格显式 inline_math=true；semantic.inline_math 可列出 title/takeaway。
  未开启的正文和独立公式路径保持兼容，详见 [行内公式协议](../../../../Total-pipe/docs/inline-math.md)。
- 复用公式 AST，按不可拆分数学区域的宽度换行，逐行取最大基线上方/下方需求并累计行高。
  不把 LaTeX 源码长度当数学宽度，也不把整段都按最高矩阵拉高。
- 树、密集公式解释块、图文混排和表格共用测量；原生 XML 保留同行文字和可编辑数学内容，
  结构审核逐项核对数学结构、换行和实际行距。宽度不足明确反馈，专业术语不截断。
- RPA 根据 native_inline_equation 能力检查 inline_math / has_inline_math 内容引用；
  原有设计阶段、Evidence 绑定和旧版消费者回退保持。普通溢出自动拆页不能切开混排公式。
- 验收：Deck Compiler 280、RPA 315、pwf2rpa 83、PWF 38 项通过，1 项缺少既有 Li 样例跳过，
  合计 716 项通过、1 项跳过。三页 PowerPoint UI、同次原生 PDF 及独立 PNG 复核均 PASS。
- 原有复合布局和表格样例的页面几何、原生 XML、内容逐项相同。行首标点收尾后，
  行内样例输出也与原生验收版本完全一致。
- QA 0 FAIL、2 WARNING、37 REVIEW；两条 OfficeCLI 溢出估计仍保留，实际原生页面无可见越界。
  数学测量、字体和科学内容审核项不自动清零。构建位于忽略目录 builds/inline-math/initial/。
