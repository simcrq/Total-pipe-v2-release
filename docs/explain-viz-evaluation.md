# ExplainViz 设计评估与实现范围

日期：2026-11-07。评估基线：`d7f9cd05e600cb48f21db0552040f986d3d46217`，
分支 `codex/audience-preview-loop`。输入是用户提供的《Deck IR 可插拔讲解可视化模块：设计与接入说明（RFC v1.0）》。
RFC 为待评估设计资料，其中示意接口不直接作为现有项目契约。
本文记录首版评估；后续已加入显式构建请求，当前范围见[构建接入说明](explain-viz-build-integration.md)。

## 结论

适合做默认关闭的试点。可以复用现有 Path IR、原生文字、递归布局、OfficeCLI 和编译 QA，
无需引入 SVG 渲染器、新编译语法或重写 Deck IR。首版的收益来自在明确区域补充讲解关系，
覆盖率受预留槽位、严格来源和现有文字容量限制；尚无测试或样本数据证明生成效果。

已有 page_design 负责观众表达与讲解方案，Scientific Visual Planner 负责整套风格及现有视觉构图，
`semantic.explanation` 负责讲解义务。ExplainViz 只提供一种可选的原生实现，不接管这些阶段，
不自动签收讲解覆盖、科学审读或最终原生验收。

## 与源码的映射

| RFC 问题 | 当前能力与本次选择 |
| --- | --- |
| slide / shape / group | `slides[].id`、`composition.graphics`；Path IR 编译为现有 shape/text，无原生编组 |
| 预留区域 | 没有通用空白 slot/spacer；使用已有 layout_tree graphic 叶子及明确背景矩形，占位许可放在旁路 slots.json |
| 单位与坐标 | 编译输出为 CSS px；模板使用局部视口，等比映射，禁止修改页面绝对坐标 |
| 对象身份 | identifier 只允许字母、数字、下划线和横线；用 `evz_`，不照抄 RFC 的冒号 ID |
| 圆弧、箭头、虚线 | 圆弧和箭头由有界路径/折线表示，参考虚线由固定短线段表达；不要求新图元 |
| 重复运行 | 检查原生路径与标签前缀；不重复追加，既有图计入整套预算 |
| 科学来源 | 当前页可见文字的事实 ID、逐关系两端绑定、显式顺序与保守线索；不从讲稿或新生成事实补全 |
| 模型接入 | 两段提示与严格 JSON Schema 交给当前 Agent；不在编译器内隐式选择模型或调用 API |
| 编译与 QA | 复用 compile_deck 比较全部原有对象，按页回退，再整套复核；后续 OfficeCLI / PowerPoint QA 保留 |

## 本次交付

- `deck_compiler/explain_viz`：默认 off 的 `enhance()`、候选筛选、受约束规格校验、
  三个确定性原生模板、真实 IR 适配器、逐页事务、整套回退及审计。
- `explain-viz-prompt / apply-explain-viz`：作为正式编译前的可选显式步骤；高级 MCP 提供对应工具。
  默认四工具状态机和普通 compile/build 不增加隐式处理。
- 提案同时绑定输入 IR 和槽位哈希，输出使用新文件并保留相对资源语义。
- `schemas/explain-viz.schema.json`、三页构造样例和回归用例；协议 `1.0` 独立于 Deck IR `2.0`。
- README、使用说明、环境清单、Agent Skill 与文档索引同步。无需新增依赖或产品发版。

相较 RFC 的工程调整：支持 prefer，但保留与 auto 相同的硬门槛；
不接受自由参数角度，固定教学几何只显示符号和“示意”；
只有当前页可见事实可作为来源，暂不接入外部事实；已有其他视觉对象的页保守跳过。
这些取舍优先缩小科学与排版风险，不能当成经过测试集校准的最优策略。

## 限制与后续

关系线索检查及标签引用不能判断任意自然语言关系的真假，否定、方向、限定范围等仍需人审。
规则只支持明确的剥离角、从上到下层叠和顺序过程，其他表达会降低召回。
不允许为获得槽位自动移动正文；即使新图能放下，只要造成原有对象变化也会回退。
已增强场景不就地重画，应从原 IR 重建。

当前回退覆盖 IR 与布局编译；后续 OfficeCLI 写入或 PowerPoint 渲染异常仍由原构建流程报告，
插件不自动覆盖候选或撤销 PPTX。结构正确、对象可编辑与科学正确性、实际视觉效果分别验收。
自动空白检测、局部重排、因果/机制对比、模型缓存和至少 40 页的人工标注决策集尚未实现。
