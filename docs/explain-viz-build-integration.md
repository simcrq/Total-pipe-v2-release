## 行为

`compile/build/generate --explain-viz-request <request.json>` 显式启用运行时集成。
请求自包含 options、slots 和已绑定源哈希的 proposal；不嵌入外部文件引用或模型调用。
Python 入口和高级 MCP 提供同名可选参数，CLI/MCP capabilities 使用同一份声明。
未传请求不运行插件；四工具接入层没有新增自动阶段。

必做的 Design 门槛先于插件。通过后，插件在内存副本上工作，利用本次实际布局提供方，
逐页检查来源、图形容量、原对象和关系，最后复用已通过检查的整套布局。
输出目录保存原输入快照、实际编译 IR、审计和 QA 摘要；源目录不写临时 IR，不改用户原文件。

提供方和请求构造新增可选 `deck_ir=` 快照参数，保留源路径用于图片/字体解析，
避免增强后被磁盘原 IR 覆盖，或临时文件放入构建目录后使相对资源失效。
溢出修复重新编译也沿用同一输入方式和原目录，继承已有修复策略。

## 失败与审计

请求无效、不可读、过期或插件拒绝时，记录 fallback 再编译原 IR；
原有编译错误仍为 FAIL，不因回退变成成功。成功新增图时加入科学人审 REVIEW。
重新构建不带请求时清理旧审计，防止误读上次结果。
构建及绑定当前产物的原生验收更新 QA 时保留 ExplainViz 摘要。

审计记录源 IR 路径、相对资源基准、请求哈希、原始输入哈希、增强 IR 哈希和最终输出 IR 哈希。
最终输出可能另经已有溢出修复，因此区分增强哈希与输出哈希；QA 绑定实际输出。
源输入快照是归档，不能因为存入构建目录就改变其相对路径基准。

文件写入/目录冲突等构建基础设施错误仍正常报错；插件不覆盖已有源文件以规避错误。
OfficeCLI 写入、原生渲染、科学人审与正式晋级继续执行原流程，尚无后端失败后的自动撤销。
本轮没有自动寻找空白区域、局部重排、新模板或四工具生成阶段改造。
