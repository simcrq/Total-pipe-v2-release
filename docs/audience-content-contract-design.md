# 科学记录与观众表达的职责重构（原设计记录）

日期：2026-11-06。以下保留实现前的设计动机和约束；本分支随后已实现页面设计 1.2，
实际字段、源文案审读和迁移规则以[内容契约](../Total-pipe/docs/content-projection.md)为准。
实现没有通过追加“说人话”提示、关键词过滤或降低门禁来声称机器已证明文案质量。
同分支已实现的选页 IR 预览与此设计独立，接口见 `Total-pipe/docs/agent-adapter.md`。

## 已确认的冲突

当前 1.1 页面设计只能引用 Story，正文和证据自动继承，设计者被要求“不重写科学内容”。
IR 又被要求保留完整 body/key_points、边界和可见讲解义务。实现者容易把“保留科学含义”理解为
“把科学记录、审稿说明和设计指令都复制成正文”。当前案例的长段落是 Agent 写入 IR 的正文，并非编译器自动造句。

这不能靠在旧要求后追加“说人话”解决。还有两个验证问题：

- `design_realization_issues` 中名为 `visible` 的语料实际含 `speaker_notes`，数值留在讲稿也能通过此项检查。
  它检查的是记录覆盖，不能充当“观众看到了关键数值”的证明。
- 科学限定、负面证据与制作过程备注没有明确的归属契约。扩大 `audience.py` 的关键词搬移规则会误伤真实局限。

## 新的权限与不变量

| 层 | 内容权威 | 可以改什么 | 必须保留什么 |
| --- | --- | --- | --- |
| 科学记录（Story） | 研究问题、推理链、观察、作者解释、证据、条件与局限 | 科学规划阶段可依据证据修订 | 数值、单位、不确定性、对照、负面结果、因果强度和来源 |
| 观众表达（页面设计） | 本页观众要理解的论点、可见文案、视觉证据及阅读顺序 | 忠实改写、把相同关系改成图或表、分配讲稿细节 | 不增加主张，不扩大条件，不改变比较对象和逻辑；保留每条内容的去向 |
| 实现（IR） | 已批准表达的原生对象与几何实现 | 选择实现能力、调整空间、换行及合法记号 | 不自行重写文案、发明核查免责声明或改变科学含义 |
| 核查记录 | 证据核查、素材可用性、制作过程、验收结果 | 记录问题与实际复核 | 不自动进入面向观众的页面 |

“内容完整”指科学语义完整且有可追溯去向，不再同时承担“逐字保留原句”和“全部页面可见”两个含义。
科学记录仍完整归档；页面是否可理解单独审查。任何自动检查都不能代替语义忠实性和观众可理解性的实际复核。

## 下一版交接数据

应版本化为新的页面设计协议，保留 1.0/1.1 的恢复行为，不能静默改变旧任务的含义。
新协议至少包含下列三份互相引用的数据，字段命名与 Schema 在实施时一并确定：

1. 科学内容分配：每个稳定 Story ref 恰好分配到一页，并保留其原始内容与证据。
2. 可见表达：页面标题、解释语句、图中标签等真正给观众看的文本，与所支持的 Story ref 绑定。
   设计指令、claim 理由、walkthrough 和“不要误读成……”的写作要求不是可见文案。
3. 内容去向：每条分配内容由哪些可见表达/原图/数据/公式承载，哪些细节进讲稿，以及为什么。
   必要条件不能仅由一个笼统的 notes 路由带走。不能用原句字符匹配判断改写的科学等价性。

关键区分是“限制了本页主张的条件”与“研究记录中的其他细节”。例如：

| 内容 | 页面要求 | 讲稿/核查记录 |
| --- | --- | --- |
| 感知与计算分开，数据转换和传输会增加延迟、能耗 | 用自然标题或带短标签的路径图表达 | 完整引言论述、证据定位 |
| 生物视觉启发 | 图上简短标“生物视觉启发（示意）” | 不能当成器件实测的核查说明 |
| 引言没有给整机节能倍率 | 背景页没有宣称节能倍率时，不强制加长篇否定句 | 在系统能耗边界讨论中保留，相关主张出现时必须可见 |
| 某准确率只在规定噪声和测试集下成立 | 对象、条件、比较结果应与数字一起可见 | 额外训练细节及完整来源 |
| D* 由 shot-noise 假设估算 | 有关 D* 的结果页必须可见估算属性及该假设 | 完整推导 |
| 对照未支持某机制或负面结果 | 放在相关论证页或明确的边界页，并保留其对结论的影响 | 完整实验细节，不能通过 notes-only 消失 |
| 本次拿到哪些文件、某图是否已检查 | 不进入正文 | QA/制作记录 |

这不是按“未报告”“不是”等词决定显示位置。相同句子是否必须可见，取决于本页是否提出会被它限定的主张。

## 验收职责也要同时改

- 记录覆盖：所有 Story 内容、数字、证据和源图仍可追溯；不以“写得更短”为由删除科学内容。
- 可见覆盖：只从实际渲染对象读取；绝不把 `speaker_notes` 算进页面。检查关键比较、数字、条件、
  不确定性和对照是否与主张同处可见范围。原图里的证据可作载体，不要求再抄一遍图中全部文字。
- 表达忠实性：在批准页面设计前，对照科学记录审查新文案。数值/来源自动检查保留，
  因果强度、条件范围、观察与解释的区分仍需 Agent 实际审读，不能伪装成确定性机器判定。
- 观众复核：只看本页渲染图，能否说出“研究对象是什么、做了什么、图支持什么结论”；
  检查指代不明、重复释义、推理跳步和核查备注泄漏。字数和字号只能反映容量，不能代表可理解。
- 实现复核：IR 可见文本与批准表达相符；不允许为了通过几何检查自动删句、缩小字体或隐藏限定。

实现时必须同时更新角色授权、交接字段、IR 来源绑定、可见/记录覆盖校验与迁移测试。
只改其中一份提示会留下原有冲突。

## 必须包含的回归案例

1. 忠实改写背景句通过，完整原句只保存在科学记录/讲稿。
2. 把关键实验条件移入讲稿、数字只留在讲稿、删除负面对照均不通过可见覆盖。
3. 定性动机不能变成已经测得系统节能；类比不能变成实验观察。
4. 真实局限仍可见，制作记录不会因包含“条件/边界”等字样被当成科学内容。
5. 1.1 旧任务可恢复，不能用新规则重解释其已批准页面。
6. 补充背景、构造示例和论文/SI 证据保持独立归属，不能通过改写绕过 supplement 泄漏检查。

## 与渲染循环的关系

科学内容和表达先各自确定，IR 实现过程中随时选页预览。未变页按内容、图像、字体、编译器和渲染器指纹复用。
Agent 必须实际打开图再改 IR，不能把生成 PNG 当作复核。默认 HTML 渲染用于尽早发现问题，
最终仍运行整套 Design、完整结构 QA 与 PowerPoint 原生验收。当前实现不宣称整套 PPTX 增量拼装或端到端提速倍率。
