# Total-pipe v2 环境清单

主链：PaperWorkflow → Story Planner → pwf2rpa → Research PPT Assistant → Deck IR
→ Deck Compiler v2 → PowerPoint native validation。

## 必需运行时

| 组件 | 用途 | 最低要求 |
|---|---|---|
| Python | PaperWorkflow、pwf2rpa、Deck Compiler、OOXML 与 PDF 检查 | 3.10+；需 Pillow、lxml、jsonschema、pdfplumber |
| Node.js | Research PPT Assistant 与 artifact-tool renderer | 22+；优先使用工作区捆绑版本 |
| Microsoft PowerPoint for macOS | golden PDF renderer | 能打开 staging.pptx 并导出 PDF |
| MinerU | PDF → Markdown/OCR | PaperWorkflow 配置的官方 CLI |

优先使用 Codex `load_workspace_dependencies` 返回的 Python、Node 和依赖目录；不要在
项目中安装另一套 artifact-tool。

## 连接器与 Skill

- `pwf2rpa` MCP 仍由 `.mcp.json` 提供，负责确定性 Story/RPA 输入转换。
- `total-pipe-deck` Skill 负责编排证据、Story、RPA 和 v2 编译门禁。
- `local-project-mcp-bridge` 仅用于把独立本地项目包装为 MCP。

M5 已从 Total-pipe 主链移除 `artifact-telemetry`、`pptx-telemetry`、旧
tencent-pptx/slidep 生成适配路径和旧 Team 编排。Research PPT Assistant 仍保留
slidep/tencent-pptx 的 telemetry adapter，用于把外部渲染事实送入 Visual QA；它们
不参与 Deck Compiler 的 PPTX 生成。Deck Compiler 直接检查交付 PPTX，并把结构与
PowerPoint 原生证据写入统一 `qa_report.json`。

## 自检

```bash
cd Total-pipe
python -m unittest discover -s tests -v

cd pwf2rpa
PYTHONPATH=. python -m unittest discover -s tests -v

cd ..
python -m deck_compiler compile \
  --ir examples/research.deck_ir.json \
  --out /tmp/total-pipe-compile-check
```

`compile` 只生成冻结 IR、layout、派生文件和 QA 报告，不生成 PPTX。

完整 PPTX 验收还需要：

```bash
python -m deck_compiler build --ir <deck_ir.json> --out <build_dir> --node <node>
python -m deck_compiler validate-native --out <build_dir> \
  --pdf <build_dir>/native.pdf --reviewer "reviewer"
python -m deck_compiler promote --out <build_dir> --ack <review_ack.json>
```

## 门禁

- `pwf2rpa --strict`：0 warning。
- RPA：normalize `valid`、plan `plan_complete`、validate-deck `valid`。
- 编译器：0 FAIL；`SPLIT_REQUIRED` 回到 Story/RPA 拆页。
- PowerPoint PDF：页数一致，逐页目检完成。
- `REVIEW`：必须有绑定 staging SHA-256 的 acknowledgement。
- final：`state.json.phase` 必须为 `final`。

端到端命令、RPA→Deck IR 映射和原生验收步骤见
[`docs/USAGE.zh-CN.md`](docs/USAGE.zh-CN.md)。
