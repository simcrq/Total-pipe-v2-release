# Total-pipe v3 环境与安装

本清单对应当前源码。产品与组件版本见 [仓库 README](../README.md#当前版本)，
端到端操作见 [中文使用说明](docs/USAGE.zh-CN.md)。

## 1. 按运行阶段准备环境

| 阶段 | 需要的环境 |
| --- | --- |
| 已有 Deck IR → 布局 / QA | Python、Pillow、lxml、主题字体；完整安装命令同时安装 PDF 检查依赖 pdfplumber |
| 生成 PPTX | 上述环境 + OfficeCLI **1.0.152+** 可执行文件，构建时检查实际属性 Schema |
| IR 编辑预览（可选） | OfficeCLI 的 screenshot/html 能力 + 可启动的 Chrome/Edge/Chromium/Firefox 或其支持的 Playwright 浏览器；与 PowerPoint 原生验收分开 |
| RPA 内容 / 版式规划 | Node.js **22+**；当前运行时无第三方 npm 依赖 |
| PaperWorkflow PDF 接入 | Python **3.12+**、其 pyproject 声明的依赖、默认 MinerU 官方 CLI 及认证 |
| PaperWorkflow 已有 Markdown 检索 | 可以跳过 OCR；该 MCP 证据检索路径使用 Python 标准库 |
| Story / Design | 支持 Skill / MCP 的 Agent；Story 保留用户选择的模型与独立 subagent provenance |
| 正式 final 原生验收 | macOS / Windows、Microsoft PowerPoint、直接逐页检查及该文件导出的 PDF |

**完整流水线统一使用 Python 3.12+**，这是 PaperWorkflow 的项目声明。
Linux / WSL 可用于证据、规划、编译和结构 QA；正式晋级仍需要 PowerPoint 原生证据。
OfficeCLI 需单独安装；源码目录不能代替可执行程序。
`advance.preview` 实际调用截图后才返回 PNG；无浏览器或宿主禁止启动时失败。doctor 不证明浏览器能够启动，
也不证明任何预览已经眼检。此可选功能不增加默认 OCR/编译的 Python 依赖。

## 2. 安装 Python 依赖

完整仓库可在根目录运行 `python3.12 install.py --client codex`（或 `--client claude|none`）。
安装器读取真实依赖清单、创建 `.venv`、做 doctor / MCP 握手后注册默认四工具服务；
`--profile advanced` 回切三服务，`--dry-run` 无安装或配置写入。详见[Agent 安装与恢复](docs/agent-adapter.md)。
doctor 除桥接版本外还实际导入 evidence 运行模块；PDF 检查包含 pdf_handler、loguru、requests、yaml
路径，发现缺失后在证据运行前报告；不运行 OCR、不上传 PDF。PDF doctor 另调用官方 CLI 的
`auth --verify` 校验环境/PWF 配置或缓存登录；只有验证成功才声明 authentication_verified。
以下为手工安装路径：

以下为在仓库根目录执行的 Bash 示例。Windows 创建同样的虚拟环境后，用
`.venv\Scripts\Activate.ps1` 激活；后续 `python` 指向该环境。

```bash
python3.12 -m venv .venv
source .venv/bin/activate

# 编译与 PDF 检查：Pillow>=10、lxml>=5、pdfplumber>=0.11
python -m pip install -r Total-pipe/requirements.txt

# 可选：公式测量使用的数学字体度量
python -m pip install matplotlib
```

完整 PaperWorkflow 环境的依赖取自其项目清单，避免把旧依赖列表复制到安装命令中：

```bash
python - <<'PY'
import subprocess
import sys
import tomllib
from pathlib import Path

project = tomllib.loads(Path('PaperWorkflow/pyproject.toml').read_text(encoding='utf-8'))
subprocess.check_call([sys.executable, '-m', 'pip', 'install', *project['project']['dependencies']])
PY
```

Windows 可将这段 Python 保存为临时脚本再运行。当前声明包括 loguru、numpy、Pillow、
openai、PyYAML、requests、tokenizers 和 tqdm，最低版本以 pyproject 为准。
pwf2rpa 自身仅用标准库。当前编译链无需 torch、本地 LaTeX 或扩散模型权重。
未安装 matplotlib 或数学结构不被其支持时，公式采用保守尺寸估计并保留 REVIEW。

## 3. OCR、配置与模型

PDF 输入默认通过 `mineru-open-api` 执行 MinerU 云 OCR；安装官方 CLI 并按其认证流程登录，
或由环境提供 `MINERU_TOKEN`。也可显式配置已有的本地 MinerU CLI 后端；
已有 Markdown / workflow 输入直接从相应阶段继续。
官方 CLI 的缓存登录无需重复导出 token。doctor 使用与实际提取相同的 PWF 配置（含 cli_command
和 api_key 优先级），不会把原始认证输出或密钥写入报告；网络不可用时报告未完成验证。

MCP 可使用默认配置；需要指定后端或缓存目录时，用 `PAPERWORKFLOW_CONFIG` 指向实际 YAML：

```yaml
paths:
  temp_dir: ./temp_markdowns
api:
  mineru:
    mode: official_cli
    cli_command: mineru-open-api
    ocr: true
```

配置搜索还包括工作区 / PaperWorkflow 目录的 `config.yaml` 和
`~/.config/paperworkflow/config.yaml`。默认云 OCR 需要网络；本地文件的检索、RPA 规划与
Deck IR 编译本身不调用模型 API。Story 和 Design 由 Agent 完成；提示包工具只准备输入。
只有使用旧批处理的模型总结路径时，才另按所选服务配置 `DEEPSEEK_API_KEY` / `OPENAI_API_KEY`。

## 4. 字体与平台

- 主题的 `font_file` / `bold_font_file` 可为文件名或实际路径；先解析 IR 所在目录、
  `TOTALPIPE_FONT_DIR` 和系统字体目录。
- `TOTALPIPE_FONT_DIR` 可含多个目录，使用当前系统的路径分隔符连接。
- Linux 同时搜索这些目录的子目录，包括 `opentype/noto` 中的 Noto CJK 集合；Debian / Ubuntu
  可安装 `fonts-noto-cjk` 与 `fonts-dejavu-core` 提供中文正文和符号字体。
- 安装正文语言所需的字形及对应字体；数学内容使用 Cambria Math，需核对 PowerPoint 实际显示。
- `large_square` / `large_diamond` / `arrowhead` 使用 Wingdings 原生项目符号；缺失时回退 Unicode，并记录字形 REVIEW。
- 替代字体与近似数学测量会记录 REVIEW；HTML fallback 不作为原生公式排版验收。
- PowerPoint 原生导出代码支持 macOS / Windows，实际可用性受桌面程序和自动化环境影响；
  需桌面已解锁，并允许 PowerPoint 自动化和对应输出目录访问。自动导出不能代替逐页检查。
- 四工具候选可用 `advance.native` 接入自动导出 / 真实 UI 复核 / 手动 PDF；低层 `validate-native`
  继续保留。全页 PNG 由 PowerPoint PDF 经 pdfplumber / pypdfium2 栅格化，Pillow 生成 contact sheet，
  均使用已有编译依赖；doctor 的 can_native_preview 仅检查依赖，不等于已导出/眼检成功。

## 5. 服务与运行检查

在相应组件目录使用同一个已安装依赖的 Python / Node：

| 服务 | cwd | 启动命令 |
| --- | --- | --- |
| PaperWorkflow | `<repo>/PaperWorkflow` | `python mcp_server.py` |
| RPA | `<repo>/research-ppt-assistant` | `node server/mcp-server.mjs` |
| Agent 默认四工具 | `<repo>/Total-pipe` | `python -m agent.mcp_server` |
| Total-pipe 低层 | `<repo>/Total-pipe` | `python -m deck_compiler.mcp_server` |

默认配置为 Total-pipe 的 `.mcp.json`；低层三服务汇总在其 `.mcp.advanced.json`，PWF / RPA 的独立配置仍保留。
手动注册时，将 cwd / 服务脚本写成实际绝对路径，
Python 指向虚拟环境；MCP 文件参数也用绝对路径。更新代码后重载服务。

在仓库根目录检查工具版本和实际能力：

```bash
python --version
node --version
officecli --version
node research-ppt-assistant/server/cli.mjs summary
```

再切到 `Total-pipe/`：

```bash
python -m deck_compiler capabilities
python -m deck_compiler compile --ir examples/inline-math.deck_ir.json --out build/env-check
```

`compile` 生成布局和 QA；生成 PPTX 再用 `build`。正式交付继续完成
[PowerPoint 原生验收、审核与 promote](docs/USAGE.zh-CN.md#6-正式-finalpowerpoint-验收与晋级)。
开发测试按本次改动的验证要求执行；安装环境检查不以固定的历史测试数量判定成功。
