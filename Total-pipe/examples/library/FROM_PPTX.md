# 从真实 PPTX 批量提炼示例页

> 做 ppt 很简单，有一个第一视觉焦点，然后控制/引导视觉焦点流动到 ppt 上所有内容就好了

> 如果你的原始输入不是 `.pptx` 文件而是**大量手机拍摄的 PPT 照片**，请直接使用配套 Skill：[total-pipe-photo-to-library](../../skills/total-pipe-photo-to-library/SKILL.md)（内含 EXIF 自动扶正、连拍去重联系表和防冲突自动打索引脚本）。

入库时，保存一套能换内容重建的讲解方式。最小交付是一份可执行的 Deck IR 示例脚本、一条可检索的索引，以及实际打开检查过的候选 PPTX。

先把视线的路线写出来。第一眼落在哪里，下一眼被什么带过去，最后读者从哪里得出结论。正文、图例、单位和限定条件放到读者需要它们的那一步。双回波页的路线是先看到两个回波峰，再顺着括号读出间隔 4 μs，最后用公式换算出厚度 5 mm。

验收时，先从缩略图找第一眼落点，再在投屏尺寸下沿整页走一遍。哪一步要停下来找对应关系，就在那一步调位置、加强同色对应，或加一个编号、短标签或引线。

## 这批复杂页是怎么做出来的

先写一句这页要让听众带走的判断，再找能让人当场验证判断的主图。把标题、图内标记、正文顺序定下来，最后选原生对象实现。下面每页的图、表、标注和结论共用一组构造读数或同一个计算模型。

| 例子 | 实际设计决定 | 可以怎样复用 |
| --- | --- | --- |
| 双回波测厚 | 让剖面上的声路和波形上的峰共享颜色，先读两个峰，再沿时间括号转到厚度公式。用真实导出的画面把数字刻度对准峰位。 | 给不同视图里的同一对象用同色、标号或引线。让观众能从结构图找到对应的测量特征。 |
| 配对噪声 | 每个样品占一行，空心点和实心点区分处理前后。同一行的两点相连，暖色只指出反向样品。把圆角标题拉近导读块，汇总指标放在导读后。 | 比较有配对关系的数据时，先保留每一对，再报汇总。例外保留在原坐标轴内，并让正文明确指出它。 |
| 数值积分收敛 | 先用双对数图看斜率，再标出橙线上用于核算的两点。侧栏表格和分式使用这两点，最后用一句话解释比值。 | 大图回答整体趋势，小表和公式让听众复算一个局部。图中证据点、侧栏数字和结论用同一来源。 |

在这些页里，原生编号告诉听众先做什么，再做什么。并列观察用同组项目符号，短圆角标签只在换组时出现。每条正文保留自己的 block ID，图注绑定到对应图、表或公式。换行和留白出问题时，先调整分区宽高、对齐和正文分组，再打开实际渲染确认。[复合布局](../../docs/composite-layouts.md) · [原生列表](../../docs/native-lists.md) · [容器与标题标签](../../docs/framed-containers.md)

## 批量转换流程

1. **先选页，再去重。** 扫一遍缩略图，按讲解关系归类，例如原图导读、配对比较、分支流程、参数核算。同类先选最清楚的一张，另一张只有带来不同的阅读顺序或对象组合时才单独入库。首页照片、节标题、只换颜色的变体按实际用途取舍。
2. **同时读画面与对象。** 打开原页，记下第一眼看哪里、沿什么顺序讲、哪些标注负责让读者返回主图。对选中的页读取单页对象树和原生表格、图表、公式，确认哪些对象能复用以及哪些数据需要源 CSV、工作表或论文补全。
3. **给每页写一条转换记录。** 保留一句论点，标出主图及其来源。写下第一视觉焦点、后续经过的内容、每一步靠什么引导，以及最后的结论。必要的对照、单位、误差定义和适用条件写在它们所限定的对象旁。
4. **按语义重建。** 用布局树表达栏、栈和组。数据可追溯时用 Chart IR 重建，表与公式用原生对象，流程用节点和连接符，科学剖面或哑铃图的局部几何用 Path IR。只有图像的证据保留为等比图片，记录来源并用原生文本做导读。需要保留明确页面坐标时，可另外走 PageScene 的构建入口。[Deck IR 协议](../../docs/deck-compiler-v2.md) · [PageScene](../../docs/page-scene.md)
5. **用可替换的素材登记脚本。** 脚本提供无参数的 `make_deck()`，资源路径相对脚本。面向公开仓库的示例使用可公开的素材和数据，并保留出处。用构造数据演示时在页面标明“构造示例”，相关正文使用 `basis=supplement`、`constructed=true` 和真实的构造来源。使用真实论文内容时按实际证据绑定及注明来源。
6. **构建、看图和入库。** 先检查 Schema、版面容量和结构 QA，按 `layout_feedback.json` 修订问题，再逐页看实际 PowerPoint 预览。重点核对阅读顺序、公式基线、图例与标注遮挡、对照条件和数据单位。每通过一页，给其登记唯一 ID、简短摘要和能识别讲解关系的关键词。后续 Agent 从索引查询，只读命中的脚本。[复杂页 QA](../../docs/complex-page-qa.md) · [示例库命令](README.md)

### 转换记录可以用一张表

| 字段 | 可填写的内容 |
| --- | --- |
| 源页 | 原文件名、页码、可公开范围、必要的图表数据位置 |
| 这页的判断 | 听众听完能复述的一句话 |
| 主图和证据 | 第一眼看什么，关键图号、数据范围、单位与对照 |
| 视线路线 | 第一眼落点、接着看什么、靠什么引导、最终落到哪个结论 |
| 重建方式 | 可编辑对象类型、版式关系和需要保留的图片 |
| 索引与状态 | ID、中英检索词、候选路径、通过或仍需回查的问题 |

可以先按源文件批量登记，再按讲解关系挑选代表页。每类先完成一页，确认读图规则，再复用代码处理同类页。

### 用现有命令检查单页

使用指定的源页和现有工具读取原对象。下面以第 7 页为例。

```bash
officecli get /path/to/reference.pptx '/slide[7]' --depth 2 --json
```

在 `Total-pipe/` 目录运行库命令。

```bash
python examples/library/catalog.py search "配对哑铃图 样品级反例" --limit 1
python examples/library/catalog.py show paired-noise-dumbbell
python examples/library/catalog.py build paired-noise-dumbbell --out /tmp/paired-noise-demo
python -m unittest discover -s tests -p test_example_library.py
```

提交自制示例时，把查询词和 ID 换成新条目的值。`build` 输出候选及结构 QA，PowerPoint 预览从候选另外导出。

### 可交给 Agent 的批量任务

> 读取指定目录的 PPTX 缩略图，按讲解关系列出代表页及原页码。对选中的每一页，先写一句论点、第一视觉焦点、视线经过每块内容的顺序和引导方式，并记录来源。再按关键词从示例库找最接近的一项。将画法写成独立脚本，并用同一份源数据生成图、表和标注。若数据缺失，标出待回查项或使用有出处的原图。逐页构建，在 PowerPoint 里从第一视觉焦点走完整页，并验证按新 ID 能检索到该页。
